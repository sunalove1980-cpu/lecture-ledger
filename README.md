# Lecture Ledger

강의 일정과 강의료 정산을 관리하고 Google Calendar의 `[G]` 일정을 가져오는 React/Vite 앱입니다.

## 로컬 실행

```bash
npm ci
copy .env.example .env.local
npm run dev
```

`.env.local`의 `VITE_GOOGLE_CLIENT_ID`에는 Google Cloud에서 만든 웹 애플리케이션 OAuth Client ID를 설정합니다.

## Google 로그인 설정

1. Google Cloud 프로젝트에서 Google Calendar API를 활성화합니다.
2. OAuth 동의 화면을 구성하고 `calendar.readonly` 범위를 사용합니다.
3. 웹 애플리케이션 OAuth Client ID를 만듭니다.
4. 승인된 JavaScript 원본에 로컬 주소와 실제 배포 주소를 등록합니다.
5. Vercel 환경변수 `VITE_GOOGLE_CLIENT_ID`에 Client ID를 저장한 뒤 다시 배포합니다.

사용자는 앱 화면에서 별도의 Client ID를 입력하지 않고 **Google로 로그인** 버튼만 누르면 됩니다.

## 루미 일정 추가 전용 동기화

- 제목이 `[G]`로 시작하고, 설명에 `등록: 루미`가 독립된 줄로 있어야 합니다. Calendar HTML 설명의 `<p>`, `<div>`, `<br>` 줄바꿈과 HTML 문자는 텍스트로 정규화한 뒤 같은 정확한 줄을 검사합니다. 문장 끝에 붙은 마커나 유사 문구, HTML 속성·스크립트·주석 속 마커는 인정하지 않습니다.
- Calendar의 실제 `created` 시각이 `2026-10-07T00:00:00+09:00` 이상이어야 합니다. 오래된 일정의 설명을 수정해도 가져오지 않습니다. 조회할 일정 시작 범위도 2026-10-07 이후입니다.
- 취소 일정과 출처/생성 기준에 맞지 않는 일정은 제외합니다. 강의료는 필수이며, 잘못된 금액이나 날짜, 응답/네트워크 오류는 전체 추가를 중단합니다.
- 같은 Google 이벤트 ID 또는 같은 날짜·시작/종료 시각·강의명·업체인 기록은 건너뜁니다. 금액이 달라도 기존 기록을 갱신하거나 연결하지 않습니다.
- v1 localStorage 배열과 기존 모든 필드를 유지합니다. 추가 전 검증 후 한 번의 `setItem`으로 저장하며, 처음 추가하기 직전 원본 문자열을 `lecture_fee_manager_lectures_v1_before_lumi_append_v1`에 보관합니다 (`original: null`은 기존 키 없음). 백업을 자동 복원하거나 덮어쓰지 않습니다.
- 백업/저장 공간 부족이나 손상된 기존 배열은 동기화를 중단합니다. 신규 0건일 때는 강의/백업 키를 쓰지 않습니다. 연결 설정은 강의 저장과 별개이며 설정 저장 실패를 따로 표시합니다.
- HTTPS의 Web Locks 지원 브라우저에서 동시 동기화를 직렬화합니다. 저장 직전 원본 변경도 확인합니다. 기존 수동 편집 기능의 다른 탭 동시 쓰기까지 트랜잭션으로 바꾸지는 않았습니다.
- 백업과 강의 기록은 해당 브라우저·앱 주소에만 존재합니다. 앱 주소를 바꾸면 기존 localStorage가 자동 이동하지 않습니다.

합성 데이터 회귀 검증 (Node 22.18+ 또는 24):

```bash
npm test
npm run build
npm run lint
```

테스트는 메모리 저장소와 가짜 Calendar 응답만 사용하며 실제 브라우저 기록, OAuth 및 Calendar 계정에 접근하지 않습니다.

상단 **동기화**(미연결 상태에서는 **구글**)는 안내 창만 엽니다. 창을 열거나 닫는 것만으로 인증·가져오기·저장이 실행되지 않습니다. 안내를 읽고 **새 일정 가져오기**를 눌러 실행합니다. 미연결 상태에서는 **구글 계정 연결 후 새 일정 가져오기**를 누릅니다. 홈의 **새 일정만 추가 · 기존 기록 보존 / 동기화 기준 2026.10.07** 표시로 새 안내를 확인할 수 있습니다.
